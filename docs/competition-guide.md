# 指尖开花竞赛答辩指南

## 1. 一句话介绍

指尖开花是一套运行在浏览器中的隔空宠物互动作品：摄像头在本机识别手部 21 个关键点，指尖位置被转换为宠物身体分区和手势动作，驱动实拍照片木偶完成摸头、奔跑、转圈、打滚等反馈；可选接入 Supabase，用匿名聚合指标证明作品被真实使用。

## 2. 演示脚本（约 3 分钟）

1. 打开首页，选择「开启摄像头」，展示摄像头小窗与手部关键点。
2. 将指尖移到宠物头部，展示低头、闭眼和呼噜反馈。
3. 张开五指，展示原地转圈、抖耳和叫声。
4. 左右挥手，展示宠物朝手势方向奔跑。
5. 双手同时接触，展示打滚与「嘤嘤嘤」音效。
6. 按 `F` 进入「指尖开花」，展示指尖控制花朵开合。
7. 打开「数据」页，说明互动次数、独立访客、摄像头启动次数、平均会话、手势分布和宠物偏好。
8. 无摄像头时使用「先看看」，鼠标指针就是指尖，保证答辩现场可降级演示。

## 3. 技术架构

```text
摄像头 / 鼠标
  -> MediaPipe Hand Landmarker（21 点）
  -> One Euro 滤波与指尖坐标换算
  -> 宠物分区触摸判定 + 轻点/抚摸/挥手/开掌识别
  -> 宠物双层状态机与动作时间轴
  -> Canvas 2D 实景、照片木偶、光影和音效
  -> 匿名事件队列
       -> 本地 localStorage（默认兜底）
       -> Supabase 匿名写入 + 聚合 RPC（配置后）
  -> analytics.html 数据看板
```

核心模块：

| 模块 | 职责 |
|---|---|
| `js/hand.js` | 摄像头、MediaPipe、关键点平滑、挥手和开掌检测 |
| `js/touch.js` | 指尖到宠物局部坐标的分区、轻点和抚摸判定 |
| `js/pet.js` | 触摸层与一次性动作层状态机 |
| `js/render.js` / `js/scene.js` | 照片木偶、实景桌面、投影和统一光影 |
| `js/services/analytics.js` | 匿名访客、会话、事件规范化和本地汇总 |
| `js/services/event-queue.js` | 批量发送、失败保留、最多缓存 200 条 |
| `js/services/supabase.js` | 会话 RPC、批量事件写入、聚合看板读取 |
| `js/analytics-page.js` / `js/dashboard-view.js` | 看板加载、失败回退和安全 DOM 渲染 |

## 4. 手势识别链路

1. 浏览器通过 `getUserMedia` 获取视频，画面不写入数据库。
2. MediaPipe Tasks Vision 在浏览器内输出每只手的 21 个关键点。
3. 关键点经过 One Euro 滤波：静止时抑制抖动，快速移动时降低延迟。
4. 食指指尖（索引 8）映射到 Canvas，再换算成宠物局部坐标。
5. 使用椭圆有符号距离判断头、脸、背、尾等分区；接触只在进入边缘时记录一次。
6. 手势规则产生动作事件，宠物状态机叠加触摸层和一次性动作层。
7. 渲染层按「实景 -> 桌面高光 -> 投影 -> 宠物 -> 情绪 -> 全局光影」绘制。

## 5. 手势与动作

| 手势 | 判定要点 | 宠物反馈 |
|---|---|---|
| 摸头 | 指尖进入头部分区 | 低头、塌身、闭眼、呼噜 |
| 张开五指 | 五指跨度大于阈值并稳定 | 原地转圈、抖耳、短叫 |
| 轻点 | 接触 90-220 ms 且位移较小 | 短叫、歪头 |
| 左右挥手 | 450 ms 内横向移动超过画面宽度 16% | 朝手势方向奔跑 |
| 双手接触 | 两只手同时接触并稳定约 240 ms | 打滚、三声嘤嘤 |
| 摸背 | 背部区域内快速往返 | 背脊抖动、身体放松 |
| 悬浮 | 指尖停在宠物周围但不接触 | 头部跟随指尖 |
| 开花彩蛋 | 按 `F` 或 `?bloom=1` | 指尖控制花朵开合与旋转 |

## 6. 数据分析定义

看板展示六项 KPI：

| 指标 | 定义 |
|---|---|
| 互动次数 | `touch_started`、`gesture_triggered`、`pet_action` 事件总数 |
| 独立访客 | 匿名 `guest_id` 去重数 |
| 摄像头启动 | `camera_started` 事件数 |
| 平均会话 | `session_end.value` 的平均毫秒数 |
| 手势种类 | 产生过事件的不同手势值数量 |
| 宠物偏好 | 互动事件最多的宠物及次数 |

匿名事件类型包括 `session_start`、`session_end`、`camera_started`、`camera_failed`、`demo_started`、`pet_selected`、`touch_started`、`gesture_triggered`、`pet_action` 和 `bloom_toggled`。

## 7. 隐私与安全边界

- 摄像头帧、关键点轨迹和用户上传的宠物照片都不上传。
- 只记录匿名 UUID、会话时长、宠物 id、手势名和有限的交互元数据。
- Supabase 匿名角色只允许插入受限事件类型，不能直接读取明细表。
- 看板通过 `SECURITY DEFINER` 聚合 RPC 获取数据，不返回访客标识和原始事件。
- 前端只使用公开 anon key；service role key 不进入浏览器和 Git。
- 未配置 Supabase 或云端不可用时，自动退回本地统计，互动功能不中断。

## 9. 常见问题

| 问题 | 处理 |
|---|---|
| 页面没有宠物 | 确认通过 HTTP 访问，而不是双击 `file://` 打开 |
| 摄像头被拒绝 | 检查地址栏权限；`localhost` 或 HTTPS 才允许摄像头 |
| 手势不灵 | 保证光线充足，手距摄像头约 40-60 cm，指尖完整入镜 |
| 云端看板显示本地模式 | 检查 `.env.local` 的两项变量并重启 Vite |
| 云端看板显示暂不可用 | 检查 SQL 是否执行、项目 URL/key 是否正确、网络是否可访问 Supabase |
| 构建后素材缺失 | 必须运行 `npm run build`，不要只运行 `vite build` 后手工遗漏运行资源复制 |

## 10. 可扩展方向

- 将手势规则抽成可配置分类器，增加捏合、点赞、双手缩放等动作。
- 记录匿名识别置信度和丢帧率，用于比较不同设备性能。
- 增加时间窗口聚合，展示每日趋势、留存和手势成功率。
- 在管理员鉴权后增加明细检索和异常事件治理。
- 为无障碍场景增加键盘、触控板和鼠标完整替代路径。
